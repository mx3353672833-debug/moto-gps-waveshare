# 构建方案

## 产品目标

> **历史方案，当前禁止照此执行或下单。** 本文件保留的是早期“自研板 + LC76G + 手机热点”独立终端路线。当前正式样机已改为 Waveshare 1.75C + 原生 iOS App，ESP32 只做 BLE 仪表端，不安装 LC76G、不通过热点请求高德。当前基线见 [微雪 + iPhone 样机基线](WAVESHARE_IOS_PROTOTYPE.md)。

构建一台以 ESP32-S3、1.75 英寸 466 × 466 圆屏显示为核心的便携摩托车导航仪。共享 UI 已统一迁移到 466 × 466 framebuffer。当前样机由 iPhone 原生 App 提供定位、路线、路况与偏航重算；独立 GNSS 和自研 PCB 作为通过样机验证后的可选方向。导航仪必须支持：

- 清晰的逐向导航；
- 偏航自动检测与重新规划；
- 周期性实时路况更新；
- 热点断开后的缓存导航、自动重连与恢复；
- 高德普通驾车路线作为样机阶段的数据源；
- 后续替换为摩托车路线服务时不修改圆屏 UI 和导航核心。

## 架构

```text
网页调试台（C 级）
  ├─ 目的地搜索、地图、轨迹回放、故障注入
  └─ WebAssembly
       └─ 共享 C/C++（A 级）
            ├─ LVGL 圆屏 UI 与资源
            ├─ RouteBundle 解码
            ├─ 路线匹配、路线推进与到达判断
            ├─ 偏航确认、重算与路况刷新状态机
            └─ 坐标处理
                  ├─ Web 平台适配器（B 级）
                  └─ ESP32 平台适配器（B 级）

自有后端
  ├─ POI 搜索
  ├─ 高德普通驾车路线与路况
  ├─ 路线重算
  └─ 标准化、压缩并返回 RouteBundle

实体设备
  ├─ 自研 ESP32-S3 + 466×466 AMOLED 圆板
  ├─ LC76G GNSS + 独立天线
  ├─ QMI8658 IMU + LIS2MDL 磁力计
  ├─ Wi-Fi 手机热点
  └─ 本地缓存
```

高德 API 密钥只存在于后端。浏览器和固件都只调用自有接口，避免密钥泄露，也让路线提供商可替换。

## 建议目录

```text
shared/
  nav_core/       路线匹配、路线推进、偏航和到达判断
  nav_state/      联网、路况刷新与重算状态机
  nav_protocol/   RouteBundle 及版本兼容
  nav_ui/         唯一的 LVGL 圆屏 UI
  assets/         字体、图标、颜色和图片
platforms/
  web/            Emscripten、Canvas 输出和模拟适配器
  esp32/          LCD、GNSS、Wi-Fi、HTTPS、NVS 和时钟适配器
web_console/      C 级网页调试台
backend/          高德 Provider、自有 API 与密钥管理
tests/
  fixtures/       路线、定位、网络和路况事件
  golden_frames/  RGB565 标准画面
docs/
```

目录可以随构建系统微调，但共享层与平台层的依赖方向不能反转。

## 数据流程

1. 网页通过自有后端搜索 POI、选择起终点并请求路线。
2. 后端调用高德普通驾车路线服务，将原始响应转换为版本化 `RouteBundle`。
3. Web 可行性版本把模拟定位样本送入共享导航核心；圆屏由共享 LVGL 代码渲染。
4. 实机版本由 GNSS 适配器提供定位样本，通过手机热点请求同一个后端。
5. 导航核心推进路线并计算下一动作；UI 只消费标准化导航状态。
6. 连续满足偏航条件后，状态机立即请求后端按当前位置重算，成功后原子替换路线。
7. 设备按策略周期性刷新路况；只有新路线收益超过阈值时才建议或执行换路。
8. 网络中断时继续使用缓存路线，本地显示连接状态并后台重连；恢复后优先处理待执行的重算或路况刷新。

## 阶段与退出条件

### 阶段 0：冻结移植契约

- 固定 466 × 466、RGB565、LVGL 共享渲染和 A/B/C 分类。
- 固定依赖方向、平台接口边界和变更前告知规则。
- 退出条件：`docs/PORTABILITY.md` 成为后续修改的验收依据。

### 阶段 1：仓库与双目标最小构建

- 建立共享层、Web、ESP32、测试和后端骨架。
- 同一份 LVGL 代码分别编译到 WebAssembly 与 ESP32。
- 先显示一帧静态 466 × 466 RGB565 圆屏画面。
- 退出条件：两端无 UI 分叉；固件构建不能依赖 Web 调试台。

### 阶段 2：标准数据协议

- 定义带版本号、校验和长度限制的 `RouteBundle`。
- 表达路线几何、机动动作、道路名、剩余距离/时间和分段路况。
- 设计全量路线原子替换，避免重算时读到半份数据。
- 退出条件：固定夹具可编码、解码、拒绝损坏数据并兼容约定版本。

### 阶段 3：导航后端

- 打通 POI 搜索、普通驾车规划、路线重算和路况刷新。
- 配置服务端密钥、超时、限流、缓存边界和可观测日志。
- 高德响应只在 Provider 内出现，对外仅返回内部协议。
- 退出条件：样例路线可稳定转换；错误、超时和配额耗尽均有明确响应。

### 阶段 4：共享导航核心

- 完成坐标标准化、路线匹配、进度推进、动作切换和到达判断。
- 实现带距离、持续时间、方向与定位精度条件的偏航确认，避免单点漂移误判。
- 实现重算去重、旧响应丢弃、退避重试、路况定时刷新和断网恢复。
- 退出条件：固定事件流在桌面测试和 WebAssembly 中产生一致状态。

### 阶段 5：网页版可行性模拟器

- 圆屏部分仅使用共享 LVGL；外围调试台可使用 HTML/CSS。
- 支持播放/暂停/倍速、拖离路线、GNSS 漂移、热点断开、接口超时、拥堵和乱序响应。
- 显示路线匹配结果、状态机、请求日志和性能指标。
- 退出条件：无需真实骑行即可重复验证偏航重算、路况刷新和网络恢复。

### 阶段 6：圆屏视觉与交互打磨

- 在真实圆形可视区内完成主转向、动作距离、道路名、剩余时间/距离、路况、偏航和连接状态。
- 字体、图标和动画均作为共享 LVGL 资源实现，并在 Web 中模拟 RGB565。
- 建立关键状态 golden frame 和 30 fps 性能预算。
- 退出条件：每项设计修改已标 A/B/C，A 级画面可由固件同源生成。

### 阶段 7：真实 GNSS 与道路场景验证

- 接入真实 NMEA/UBX 日志回放，再接实体 GNSS。
- 覆盖城市高楼、平行辅路、高架上下层、隧道、低速掉头、错过路口和短时漂移。
- 调整偏航阈值时以测试夹具固化，避免只针对单条路线优化。
- 退出条件：主要场景不会频繁误重算，真实偏航能在可接受时间内触发。

### 阶段 8：实体板一致性验证

- 接入 LCD、GNSS、Wi-Fi 热点、HTTPS、NVS 与断电恢复。
- 用同一事件流比较 Web 与 ESP32 的状态哈希和 RGB565 帧缓冲。
- 测量 RAM、PSRAM、Flash、帧率、启动时间、网络流量、温度与持续运行稳定性。
- 退出条件：核心功能无需在固件另写一遍；热点息屏场景可持续运行并自动重连。

### 阶段 9：自研主板与 EVT 外壳

- 冻结固定料号的屏幕/FPC、电池、GNSS/2.4 GHz 天线和车把安装方向。
- 完成 Rev A 原理图、约 Ø51–52 mm 四层圆板、嘉立创生产包和 5 块 PCBA 联调。
- 外壳从 Rev A 开始与天线和 PCB 协同设计，但只先做全塑料 EVT 壳；屏幕、电池、RF、磁场、散热和装车振动通过后，才冻结 CNC 铝前框和塑料 RF 后盖。
- 退出条件：Rev B 主板与外壳通过装车、热点、GNSS、指南针、功耗、雨淋和振动测试，制造文件无未解释 ERC/DRC 错误。

详细器件、结构、交付物和门槛见 [自研一体硬件与外壳执行方案](CUSTOM_HARDWARE_PLAN.md)。

## 必须尽早验证的风险

### 坐标系与道路匹配

GNSS 通常输出 WGS84，高德路线数据使用 GCJ-02。坐标转换必须位于明确、可测试的边界，所有位置样本和路线对象都要携带坐标系标识，禁止靠默认约定混用。

仅做数学转换仍不足以解决高架上下层、平行道路和城市峡谷问题。阶段 7 必须使用中国实际道路日志验证方向、速度、定位精度和路线拓扑共同参与的匹配策略。

### 高德授权、配额与产品化

样机阶段使用普通驾车路线只代表技术可行，不自动代表可用于量产硬件或商业服务。在产品化前必须向高德确认并保留书面结论，至少覆盖：

- 车载/硬件终端场景是否需要额外授权；
- 路线、路况和 POI 数据可否传输到设备、缓存多久以及能否离线使用；
- 普通驾车与摩托车路线服务的准入、计费、调用配额和展示要求；
- 坐标转换、衍生数据、日志留存和隐私合规边界。

如果授权不允许长期保存原始路线，内部协议和缓存策略必须按许可收紧。任何演示版密钥和个人配额都不能直接进入量产方案。

### iPhone 热点稳定性

ESP32-S3 使用 2.4 GHz Wi-Fi。必须在真实 iPhone 息屏、锁屏、来电、弱信号、移动网络切换和热点短暂断开的情况下测试，而不是只验证桌面常亮场景。设备侧应具备保活、自动重连、指数退避、缓存导航和明确的离线状态；“稳定”以长时间实测结果为准，不能仅依据接口能力宣称。
