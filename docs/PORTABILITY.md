# 可移植性契约

## 目标

网页版不是固件界面的视觉参考稿，而是共享圆屏代码在浏览器中的运行版本。圆屏 `NavPresenter + LVGL` 只维护一份，由 Web 和 ESP32 编译；导航 `NavApp + NavCore` 也只维护一份，由 Web 和原生 iOS 桥接使用。当前 ESP32 是 BLE 仪表端，不在设备上重复运行路线规划、偏航重算或高德请求。

本文是项目的硬约束。任何新功能或视觉修改在实现前都必须标明 A、B、C 级；如果不能在固件上原样呈现，必须在动手前说明，不能等到移植阶段再暴露。

## 固定显示基准

| 项目 | 基准 |
| --- | --- |
| 逻辑与物理分辨率 | 466 × 466 |
| 像素格式 | RGB565 |
| 屏幕形状 | 圆形；四角视为不可见区域 |
| UI 引擎 | LVGL，共享同一版本、配置和资源 |
| Web 输出 | LVGL 软件帧缓冲原样送入 Canvas，不用 Canvas 重绘组件或文字 |
| 固件目标 | ESP32-S3，优先选择带 8 MB PSRAM、16 MB Flash 的型号 |
| 初始性能目标 | 30 fps；最终以实体屏幕和总线测试为准 |

当前 Web、Presenter 与 Waveshare 实机统一使用 466 × 466 基准。若以后更换为其他分辨率或像素格式，必须单独评估并明确告知：像素级外观、文字换行、资源尺寸和动画时序不再保证原样迁移。

## A/B/C 可迁移等级

| 等级 | 定义 | 典型内容 | 验收方式 |
| --- | --- | --- | --- |
| A：同源移植 | 对应运行端编译同一份业务或 UI 源码和资源 | Web/iOS 共用 `NavApp + NavCore`；Web/ESP32 共用 `NavPresenter + LVGL`、字体、图标和页面布局 | 核心 fixture 产生相同状态；相同快照产生相同 RGB565 关键画面 |
| B：同契约适配 | 上层行为和接口不变，但平台底层分别实现 | Web Geolocation/`fetch` 与 iOS Core Location/URLSession；iOS BLE Central 与 ESP32 BLE Peripheral；浏览器输入与 CST9217 | 两端通过同一协议 fixture；错误码、超时、握手和重试语义一致 |
| C：仅 Web | 只服务于开发、观察或故障注入，不进入固件 | HTML/CSS 调试台、高德完整地图、鼠标拖车、时间轴、日志视图、浏览器开发工具 | 与圆屏共享代码隔离；构建固件时不可被依赖 |

### A 级允许的例外

A 级强调同一份源码、资源和行为，不承诺不同 LCD 面板在亮度、色温、可视角度上的物理观感完全一致。Web 必须模拟 RGB565 量化，字体必须使用项目内生成的 LVGL 字体，不能调用浏览器系统字体。

### B 级边界

B 级适配器只能负责平台能力，不能偷偷复制业务逻辑。例如：

- 网络适配器只负责请求、超时、取消和返回数据，不能在 Web 与 iOS 两端分别实现重算策略。
- 定位适配器只提供标准化定位样本，路线匹配和偏航判断必须留在共享核心。
- 存储适配器只保存版本化数据，路线数据格式和兼容逻辑必须共享。
- BLE 适配器只负责可靠传送版本化快照与命令，不能在 ESP32 再复制一套导航核心。

## 实现约束

- 圆屏内部禁止使用 HTML、CSS、DOM、浏览器 SVG 滤镜、系统 Emoji、Lottie、GIF 或视频。
- 字体、图标、颜色、布局常量和动画曲线均进入共享资源或共享源码。
- 不依赖浏览器字体排版、亚像素抗锯齿、毛玻璃、模糊阴影等 ESP32 无法等价实现的效果。
- 高德密钥不得进入 WebAssembly、网页前端或固件；路线和路况统一经过自有后端。
- 共享核心不直接调用浏览器、ESP-IDF、Arduino 或具体屏幕驱动 API。
- 路线提供商数据先转换成版本化的内部 `RouteBundle`，UI 与导航核心不得依赖高德原始响应结构。
- 每个跨平台接口都必须能注入固定 fixture，以便无硬件时验证数据契约。当前 iOS 测试版可以从明确标注的按钮启动 B 级内置演示适配器，ESP32 也可在导航页长按开关本机演示路线；两者都必须经过正式共享核心、协议或 Presenter 链，且不得替代真实路线的正常/生产导航入口。
- 手机定位/路线坐标在共享 C++ 中分别使用 `Wgs84Point`/`Gcj02Point`；禁止以无标记通用点类型跨越边界。
- Web 与 iOS 入口只能向共享 `NavApp` 注入事件并执行其返回命令。ESP32 只能解码 BLE 快照、更新 `NavPresenter`，以及把触摸命令回传手机，不能直接复制或篡改权威导航状态。
- 圆屏上电 Logo 淡入淡出、页面指示点及其 5 秒无操作隐藏规则属于共享产品交互；触摸或换页必须让指示点短暂重现。ESP32 本机演示只能由导航页长按显式触发，退出后继续以 iPhone 快照为权威。
- 真实道路夹具必须记录来源、坐标系、转换和许可：当前济南白色选中路线与灰色周边道路均来自 OpenStreetMap way，展示时保留 `© OpenStreetMap contributors` 并遵守 ODbL。高德只用于 iOS 在线演示或正式导航的实时联网请求，响应不得固化进演示夹具；正式在线道路层只有在开通交通态势高级 API 并取得车载/智能硬件投射书面授权后才能接入。

## 修改前检查

每次实现功能或视觉变更前，记录以下内容：

1. 可迁移等级：A、B 或 C。
2. 是否改变 466 × 466、RGB565、字体、内存、Flash 或帧率预算。
3. 如果是 B 级，两端适配器分别是什么，行为契约如何验证。
4. 如果是 C 级，为什么只用于调试，以及它与共享代码如何隔离。
5. 若无法在固件原样呈现，先说明具体差异和替代方案，得到确认后再实现。

## 一致性验收

- Web 与 iOS 共享同一组路线、定位、网络和时钟 fixture；iOS/ESP32 共享同一组 BLE 黄金帧。
- 每个输入事件后比较 Web/iOS 导航状态，偏航、重算、断网恢复和到达结果必须一致。
- 关键 UI 状态保存 RGB565 golden frame；Web 直接输出该格式的帧缓冲。
- 固件构建不得链接 `web_only` 目录，Web 调试台不得包含圆屏业务逻辑的第二份实现。
- 任何只能“视觉近似”的内容都不能标记为 A 级。
