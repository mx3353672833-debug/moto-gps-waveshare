# 圆屏产品界面与导航模拟执行方案

> 状态说明：本文记录已经完成的圆屏与网页回放开发阶段。这里的 Web 回放仍只用于电脑端视觉/协议检查；后续 App 测试版和 ESP32 固件分别增加了明确标注的济南真实道路演示，正常/生产导航仍使用真实手机定位与线上路线。当前真实高德网关已就绪，ESP32 不接 GNSS、不直接请求 HTTPS。圆屏 `NavPresenter + LVGL` 的同源迁移约束仍然有效。

## 1. 本轮目标

本轮只完成“产品界面 + 可重复导航模拟”，不选购硬件、不设计外壳，也不把演示结果包装成真实高德或百度导航。

交付结果是一套可在浏览器直接体验的 466 × 466 圆屏程序：启动 Logo 淡入淡出结束后进入车头朝上的导航页，可通过触摸/鼠标横向切换到独立马表和指南针；音乐控制先做成可开关的附加页和交互模拟。圆屏内所有正式画面均由共享 C/C++、LVGL 和项目内资源生成，固件继续编译同一份代码。

参考图和视频提供的是产品方向，而不是要求把手机截图、视频或网页贴到圆屏里。应提取并落实以下核心特征：

- 深黑底色、粗白路线、少量冷色状态光，画面在骑行中一眼可读；
- 车辆箭头固定朝屏幕 12 点方向，路线在箭头下方旋转和平移；
- 只显示当前决策需要的信息，不显示完整地图瓦片、POI 密集标注或网页控件；
- 有效路线中，圆周可承担路线进度、路况或刻度等次要信息；没有路线时不显示空进度，中心区域保留给路线、速度和方向；
- 触摸操作数量少、目标大，戴手套和颠簸场景下不依赖细小按钮。

## 2. 可移植等级

沿用项目现有契约：

- **A：同源移植**——Web 与 ESP32 编译同一份共享代码和资源，固件可以原样呈现。
- **B：同契约适配**——行为和数据接口一致，但浏览器与实体设备分别接入平台能力。
- **C：仅 Web**——只用于回放、注入、观察和调试，不进入固件产品界面。

本轮每项交付的等级如下。

| 编号 | 功能或交付 | 等级 | 固件迁移结论 |

### 本轮必须提前说明的非原样迁移内容

以下内容不能宣称“网页做好后直接原样搬进固件”：

1. 网页外层调试台、滑杆、日志和故障注入面板属于 C 级；固件只有圆屏内部画面。
2. Web 的鼠标/触摸、虚拟轨迹和浏览器时钟会换成实体触摸、GNSS/航向源和设备时钟，属于 B 级。
3. 音乐控制页面可以 A 级迁移，但网页无法证明它能控制 iPhone 上的 Apple Music 或网易云音乐；真实控制链必须在硬件阶段验证。
4. BLE HID 只能稳定兜底播放/暂停、上一首和下一首；iPhone 的 Apple Media Service（AMS）可额外提供播放器/曲目元数据和条件性的 `LikeTrack` 命令。AMS 不提供“当前是否已喜欢”状态，命令写入成功也不代表 App 一定执行，因此“喜欢”只能按当前播放器能力动态出现，并显示“已发送”，不能伪装成可切换的收藏状态。
5. Web、ESP32 和 iOS 离线导航模拟使用固定的济南真实道路夹具和合成的沿线位置推进，不是实时在线导航。白色选中路线与灰色周边道路均来自真实 OSM way；iOS 在线演示会逐次实时请求相同两处 POI 的高德路线，但不把响应固化进夹具。真实 POI、在线规划、偏航重算与路况 Provider 继续与演示入口明确分离。

## 3. 圆屏信息架构

### 3.1 页面顺序与触摸规则

默认页面顺序为：

```text
导航 ←→ 马表 ←→ 指南针 ←→ 音乐（功能开关启用时）
```

- 左右滑动切换页面；页面切换只沿水平方向，垂直抖动不触发。
- 导航进行中，导航页是默认页；页面切换不得暂停导航核心或轨迹回放。
- 所有触摸热区至少按 44 × 44 逻辑像素设计，音乐主控按键应更大。
- 导航页不放需要精确点击的小按钮。页面位置用极弱的圆点提示；上电、触摸或换页后显示，5 秒无操作自动隐藏，避免持续抢占路线视线。
- 减少动态效果开启时，页面切换和路线更新改为立即刷新或短时淡入，不做惯性滑动。
- 是否需要“转向临近时自动回到导航页”先作为可配置策略，不在首版强制，以免用户切到马表后被频繁打断。

### 3.2 导航页

导航页是本轮的主画面，视觉和行为必须优先于其他页面完成。

固定元素：

- 车辆箭头位于圆心略下方，始终指向屏幕 12 点；
- 当前选中路线使用高亮白或冷白色粗线，外缘使用低饱和冷色增强夜间轮廓；
- 已驶过路线降为深灰，不与前方路线争夺注意力；
- 周边道路以细灰线显示，并与白色选中路线使用相同的车头朝上变换；
- 动作图标和距离位于下方安全区；距离只显示大号数字与独立的 `m` / `km` 单位，不增加说明性标题；
- 限速采用小型红白圆牌，只有数据存在时显示；
- 圆周细弧用于有效路线的进度和前方路况，颜色数量保持克制；
- 重算、断网、到达等状态使用短文本和颜色变化，不覆盖车辆箭头。

页面不显示完整地图瓦片、楼宇、POI、搜索框和长道路列表。路线几何必须来自数据，不能只按“左转/右转”切换几套静态图。
没有真实路线且未显式开启演示时，动作图标、距离、圆周路线进度和限速牌全部隐藏；等待手机或等待路线是连接状态，不能呈现直行 `0 m`。存在路线但没有可信限速时也隐藏限速牌。

### 3.3 独立马表页

马表保持“单纯的马表”：

- 中心显示大号整数速度；
- 下方只显示 `km/h`；
- 圆周刻度用于形成稳定的仪表感，并随速度平滑推进；
- 定位无效时显示 `--`，不把最后速度长期伪装成实时速度；
- 首版不加入平均速度、里程、海拔、加速度或排名等附加信息。

### 3.4 指南针页

- 固定基准线指向屏幕 12 点，刻度环反向旋转；
- 显示 `0–359°` 和 `N / NE / E / SE / S / SW / W / NW`；
- 航向无效或精度不足时明确降级，不显示伪精确度数；
- 低速时航向来源可能需要磁力计或 IMU/GNSS 融合，传感器选型后置，本轮用模拟航向验证画面和算法接口。

### 3.5 可选音乐页

首版只验证安全、简洁的控制布局：

- 中央播放/暂停；
- 左右为上一首/下一首；
- “喜欢”单独显示但由 AMS 当前能力开关控制：平台不支持时隐藏；
- Web 不假设能读取真实曲名、封面、歌词或收藏状态；实体端以后可读取 AMS 提供的有限元数据，但仍没有可靠收藏状态；
- 导航转向提示拥有更高优先级，但首版不做音频混音或语音播报。

## 4. 车头朝上导航的实现逻辑

用户看到的关键效果是“箭头不转，路线随车转”。这不是把一个右转图标放到画面中心，而是每帧从真实路线几何生成局部视图。

### 4.1 输入

共享路线视图至少消费：

- 当前匹配到的路线进度；
- 当前坐标及坐标系；
- 稳定后的车辆航向；
- 当前速度和定位精度；
- `RouteBundle` 中的路线折线、动作点和分段路况；
- 屏幕逻辑尺寸、前看距离和圆形裁剪半径。

### 4.2 投影步骤

1. 由路线匹配结果定位车辆在折线上的里程位置。
2. 截取车辆后方短距离和前方较长距离的局部路线窗口。前看距离根据速度、下一个动作距离和弯道密度调整。
3. 将局部经纬度转换成当前点附近的米制东/北坐标；路线与当前位置必须处于同一坐标系。
4. 以稳定航向旋转局部坐标，使“车辆前方”始终映射到屏幕负 Y 方向。
5. 将车辆锚点放在 `(180, 190)` 附近而不是绝对圆心，为前方路线留出更多空间。
6. 对折线做距离重采样、尖角限制和屏幕外裁剪，再生成 LVGL 线段；禁止由浏览器 Canvas 绘制第二份路线。
7. 根据路线进度切分已驶过、当前和前方路段；路况只改变对应分段或圆周提示，不整屏变色。
8. 新 GNSS 样本到达时平滑更新位置与航向。偏航重算成功后原子替换路线，并以短过渡避免路线瞬间闪烁。

### 4.3 航向稳定规则

- 正常行驶时优先使用经过精度与速度门限过滤的 GNSS course-over-ground。
- 低速或停车时冻结最近可信航向，或使用未来硬件提供的低速航向源；不得让路线因 GNSS 噪声不停旋转。
- 航向突变先做限速/插值，真实掉头则允许在短时间内完成大角度变化。
- 无可信航向时退化为“路线切线朝上”，同时在状态中标识该降级，避免伪装成精确指南针。

### 4.4 模拟路线

当前固定夹具位于济南大数据产业基地 D 栋周边：白色选中路线与灰色背景道路均由 OpenStreetMap 上可核验、物理连通的真实 way 组成。OSM 的 WGS84 坐标统一转换为 GCJ-02 后同场绘制；分发和展示时保留 `© OpenStreetMap contributors` 署名并遵守 ODbL，way 明细见 [演示数据说明](../shared/demo_fixture/README.md)。高德响应不会固化进此夹具。

夹具覆盖以下画面：

- 直行进入缓弯；
- 临近 90° 右转；
- 转弯过程中路线连续旋转；
- 通过路口后新道路重新朝上；
- 灰色周边道路与有可信数据时的速度限制；
- 人工偏航后进入重算，再切换到一条新路线；
- 路况从畅通切换为缓行/拥堵；
- 最终到达。

轨迹播放不是简单递增百分比。每个样本至少包含位置、时间、速度、航向和精度，才能检验车头朝上、马表和指南针三页是否使用同一真实状态。

## 5. 共享数据与模块边界

目标依赖关系保持为：

```text
Web 夹具 / 以后实体传感器（B/C）
        ↓ 标准事件
NavApp → NavCore → NavPresenter（A）
        ↓ 只读展示状态
路线视图投影 + 页面状态机 + LVGL（A）
        ↓
WASM 帧缓冲 / ESP32 LCD 驱动（B）
```

需要扩展的展示状态包括：

- 当前页面；
- 速度、航向、航向有效性和限速；
- 当前时间是否有效；
- 路线局部窗口或生成局部窗口所需的只读路线引用；
- 可选音乐能力位和按钮反馈状态。

平台入口仍只能向 `NavApp` 或专用输入适配器提交事件，不能为了演示直接改 `moto_ui_state_t`。模拟速度、航向和路线也必须经过公开事件契约，保证将来替换成 GNSS 时不改 UI 业务逻辑。

音乐事件与导航状态分离。建议只定义 `PlayPause / Previous / Next / Like` 等意图，平台适配器返回“支持、已提交或失败”；共享 UI 不直接依赖 Apple Music、网易云、iOS 或浏览器 API。

## 6. 分阶段执行与退出条件

### 阶段 R0：冻结参考画面与验收帧

- 确认导航、马表、指南针、音乐四页的信息层级和页面顺序；
- 从参考视频确定车辆锚点、路线粗细、前看范围和夜间对比度；
- 固定一套直行、临近转弯、转弯中、转弯后、偏航、重算、断网和到达状态。

退出条件：每个状态都有明确输入和预期画面，后续不靠手工拖 UI 判断是否正确。

### 阶段 R1：扩展共享展示契约

- 增加页面、速度、航向、限速和有效性字段；
- 增加局部路线视图的数据结构或共享投影接口；
- 保持结构有固定容量和明确上限，避免为 Web 使用无界容器；
- 原生测试覆盖默认值、边界值和无效数据。

退出条件：Web 和 ESP32 目标均可编译；平台入口没有直接写 LVGL 状态。

### 阶段 R2：建立页面容器和触摸分页

- 以一个共享 LVGL 根容器管理四页；
- 实现横滑阈值、方向锁、防抖和大触摸区；
- 页面切换效果遵守 RGB565 和帧率预算；
- 音乐页由编译/运行能力开关控制。

退出条件：鼠标拖动和触摸事件均可稳定切页，连续滑动不会丢失页面状态。

### 阶段 R3：完成车头朝上导航页

- 实现局部路线投影与固定车辆箭头；
- 加入动作图标、大号距离数字 + 单位、灰色周边道路、白色选中路线，以及按数据有效性显示的限速、圆周进度和路况；
- 验证无路线时动作、距离、圆周进度与限速全部隐藏，不出现直行 `0 m`；
- 接入偏航、重算、断网和到达状态；
- 使用模拟轨迹验证转弯前后路线连续变化。

退出条件：播放夹具时车辆箭头始终朝上，路线形状随位置和航向连续变化；画面不是静态动作图。

### 阶段 R4：完成马表和指南针

- 两页使用与导航相同的样本速度、航向和时间；
- 验证低速、零速、无效定位、359°→0° 和航向跳变；
- 控制动画更新频率，避免数值抖动和无意义重绘。

退出条件：页面切换不改变数据源；边界状态有明确降级画面。

### 阶段 R5：扩展 Web 模拟台

- 将合成轨迹改为带时间、速度和航向的样本序列；
- 增加当前页面、速度、航向、限速和音乐能力注入；
- 保留播放/暂停/倍速、进度、偏航、网络和路况控制；
- 外层调试台明确标记为 C 级，不参与设备画面截图。

退出条件：不连接真实地图或硬件也能完整演示一次导航、转弯、偏航重算、马表和指南针。

## 8. 明确后置的工作

### 高德/百度真实接入

本轮当时使用固定 `RouteBundle` 验证产品交互和共享渲染；此后的高德 POI 搜索、普通驾车路线、偏航重算和实时路况链路已经接通，原生 App 还会按手机当前位置优先搜索附近地点。真实数据继续经过自有后端，密钥不进入 App、网页或固件，并保留 Provider 可替换边界。

普通高德路线接口只返回选中路线，不提供完整周边道路网。正式在线灰色道路层需要另接高德“交通态势查询”高级 API 的 `extensions=all` / `roads[].polyline`，并在车载或智能硬件投射前取得高德明确书面授权；未开通、未授权时宁可只画真实选中路线，也不能生成随机支路或复用固定演示道路。

百度是否作为第二 Provider，待高德真实链路跑通和授权边界确认后再排期；不能为了同时接两家而复制导航核心或圆屏 UI。

### 硬件采购

主板、圆形触摸屏、GNSS、低速航向传感器、供电和电池本轮全部后置。网页方案会保留固定资源上限和 B 级输入接口，但在屏幕接口、亮度、触控芯片、户外可读性和功耗测量前不下采购结论。

### 外壳

外壳仍是整个项目最后一步。只有屏幕尺寸、PCB、天线、供电、散热、防水、按键/触摸和车把安装位置全部稳定后，才开始结构、材料、密封和打样方案，避免重复开模或打印。
