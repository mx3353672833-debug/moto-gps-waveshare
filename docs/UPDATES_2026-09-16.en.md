# 2026-09-16 update and verification scope

[Project website](https://maler.top/moto-gps/) · [Back to project overview](../README.en.md) · [Website source and deployment](../website/README.md)

This round focuses on the **Waveshare 1.75C round display + iPhone** and synchronises recent source and documentation.
The iOS project version is **0.3.0 (5)**, with release preparation changes and a completed local Release archive.
It is not yet distributed through TestFlight, and there is no App Store download.
The public source retains an example gateway and generic signing configuration; configure your own service and signing to build and install it.

## Native iPhone interface

- The main flow is "Depart → Route → Navigating", using native navigation bars and grouped lists.
- System light/dark appearance and Dynamic Type large text are supported; display connection status and details are in "My Round Display".
- Real place search, recent places, route preview and candidate selection remain available; the demo opens directly from the home screen.
- Demo position and movement are explicitly marked as simulated; it first requests an online route for the fixed Jinan scenario, then uses an included route if that fails.
  Live navigation uses the phone's location and never automatically falls back to demo positions or routes.

## Online maps by default and offline downloads

With a working gateway configured, surrounding roads and buildings load online by default from OpenStreetMap / Protomaps.
The phone stores maps and selects a window around its position, then sends it to the display over BLE.

| Entry or capability | Current behaviour |
| --- | --- |
| Automatic surrounding maps | Load and cache with position changes; use existing local data when the network is unavailable |
| Download City Map | Search a city or district and preview the administrative area before downloading |
| Download This Route's Surroundings | Save a background-map corridor of approximately one kilometre around the selected route |
| Download management | Pause, resume, remove downloads and clear automatic cache |
| Phone storage budget | 128 MB automatic cache and 512 MB manual downloads; duplicate tiles are stored once |
| Jinan base map | The existing bundled SQLite map remains a fallback within its coverage |

Offline downloads store the road and building background. Place search, new route planning, online rerouting and live traffic still depend on the network.
Map density depends on the source data; missing areas are not filled with invented roads or buildings.
Each display window is still limited by road/building and vertex counts, so this does not guarantee complete nationwide coverage or the presentation of a mature navigation product.

The backend adds tile caching, city-boundary queries, concurrency and request-size limits, and separate map/city rate limits.
Concurrent requests for the same tile are combined, and existing cache is retained during a temporary source outage.
Long-term deployments should use stable data sources with appropriate usage permission and retain OSM attribution and licence links.

## BLE, privacy and release preparation

- BLE heartbeats now carry elapsed time for the current app session, restarting for a new session after reconnection; phone system uptime is used only for local timing and is no longer written into the heartbeat payload.
- Added `PrivacyInfo.xcprivacy` with declarations for current data types and use of UserDefaults, file timestamps and system boot-time APIs.
- Added a "Privacy and Data" page describing location, routes, Bluetooth, music, map caches and server logs; it is accessible without the display.
- Prepared release configuration and review materials for 0.3.0 (5). Developer-account setup, build upload and review steps still need completion before distribution.

For your own deployment or modified service, review the privacy declarations against actual server logs, data retention and privacy policy.
This repository does not include developer accounts, certificates, device identifiers or private review contacts.

## Work still in progress

- **Traffic-light countdown and live road speed limits are not connected.** Light counts or demo speed limits are not treated as live road data.
- Online traffic data is connected; per-segment route colouring and the display of unknown or stale data remain in progress. Old data must not be treated as current traffic.
- Routes currently use AMap's standard driving service and do not guarantee avoidance of motorcycle-restricted roads.
- Continue verifying cross-city route consistency, online/offline transitions, background navigation, BLE reconnection and display readability while riding.
- Work on the B1 phone companion board and V3 enclosure is paused. Historical A1/R4 engineering material remains available; publishing it does not mean prototyping or production acceptance has resumed.
