# 微雪 1.75C + iPhone 导航样机实施基线

## 1. 当前样机边界

本阶段不制作自研 PCB，也不安装独立 GNSS。硬件使用已经购买的
`Waveshare ESP32-S3-Touch-AMOLED-1.75C`，手机端使用原生 iOS 应用。

- iPhone 是导航数据的唯一权威端：持续定位、速度/行进方向、高德路线、
  路况刷新和偏航重算都在手机侧完成。
- ESP32 是确定性仪表端：接收版本化 BLE 数据，使用共享
  `NavPresenter + LVGL` 渲染导航、马表、指南针和音乐四页。
- 网页仍是同一套 466 × 466 LVGL 画面的快速调试入口，不再承担锁屏后
  持续导航这一项做不到的职责。
- 原厂 32 MB Flash 完整备份后已完成首次真机烧录与启动验证。当前 App 测试版
  提供明确标注的内置导航演示，固件导航页长按也可开关本机演示路线。App 在线
  演示与正常导航逐次请求高德实时路线；Web、ESP32 本机演示和 App 断网回退使用
  项目内真实 OSM 夹具，高德响应不写入源码或夹具。

## 2. 数据与控制链

```text
iPhone CoreLocation
        │  WGS84 fix / speed / course
        ▼
SharedNavigationRuntime / shared NavApp + NavCore
        │                       └── HTTPS ──> MOTO Gateway ──> 高德 Web 服务
        │                                  │
        │  route / traffic / reroute       └─ Key 只留在服务器
        ▼
BLE Display Snapshot + GCJ-02 route window
        │
        ▼
ESP32 BLE adapter → NavSnapshot → NavPresenter → LVGL 466×466 → CO5300
        ▲                                                     │
        └──────── DeviceCommand（触摸翻页/媒体键）─────────────┘
```

ESP32 不重新请求高德，也不维护第二套路线状态机。这样断线重连后，iPhone
只需重发最新完整快照和当前局部路线窗口，仪表即可恢复，而不会依赖某个
丢失的增量事件。

当前原生 App 还会单独取得一份手机位置用于地点搜索偏置：网关优先返回当前位置
50 km 内的 POI，近场无结果再回退全国/区域文本搜索。该一次性搜索位置源不替代
导航开始后的高精度、可后台 Core Location 数据源。

演示两端固定为“山东省大数据产业基地 D 栋附近 → 浪潮集团（总部）附近”。iOS
在线时使用这两个 POI 每次实时请求高德并沿当次 polyline 推进；断网时才回退到
35 个路线点、约 1.49 km 的 canonical OSM 路线。OSM 端点距 D 栋 POI 约 70 m、
距浪潮入口约 53 m，文案只称“附近”，不把缺失入户连接补成道路。灰色背景同样
来自 OSM，共 192 个点、24 个独立 road span，累计约 9.98 km；当前仍是该演示
走廊的真实道路窗口，不代表已经内置整座济南地图。

## 3. 四个页面的数据来源

| 页面 | 显示内容 | 数据来源 | 无手机时行为 |
|---|---|---|---|
| 导航 | 有效路线中的标准动作图标、大号距离数字 + 单位、车头固定箭头、灰色周边道路、白色选中路线，以及有可信数据时的限速和路况 | iOS + 获授权的道路数据源 | 显示连接生命周期；只有显式开启的本机 Demo Ride 才使用 OSM 路线继续演示，否则不显示旧动作、距离、路线进度和限速 |
| 马表 | 当前速度 | iPhone `CLLocation.speed` | 超时后归零并标记陈旧 |
| 指南针 | 当前行进航向和方位 | 行驶中使用 iPhone `CLLocation.course` | 静止时不能保证真北方向 |
| 音乐 | Apple Music 曲名/歌手和上一首、播放暂停、下一首 | iOS `systemMusicPlayer` 适配器 | 未授权或无队列时保留页面但不伪造曲目信息 |

板载 QMI8658 是六轴 IMU，不是磁力计。它可以检测姿态、震动和转动，不能
独立给出绝对东南西北。样机行驶时使用 GNSS course，正好满足“箭头永远朝
车头前方、道路随转弯旋转”的核心需求；若后续要求停车时也显示可靠真北，
再增加 LIS2MDL/IIS2MDC，并做整机磁校准。

## 当前启动与测试交互

- iOS 使用黑底白色 `MOTO GPS` Launch Screen；ESP32 上电在 1.25 秒节奏内播放同名 Logo 的淡入、停留与淡出动画。
- 圆屏页面指示点在上电、触摸或换页后显示，5 秒无操作自动隐藏，避免长期占用骑行视线。
- 导航页长按可开关 ESP32 本机演示路线；演示快照和路线几何仍经过正式 `NavPresenter → LVGL` 路径。
- App 测试版的“演示导航”在线时实时请求 D 栋到浪潮总部的高德路线，失败时回退 canonical OSM 路线；两条路径都经过共享 `NavApp → NavCore → BLE` 链。实际“开始导航”使用搜索选中的真实 POI、真实手机定位与实时线上路线。
- 距离区不显示说明性标题，只显示大号数字和 `m` / `km` 单位；这个数值表示距下一次转向、掉头或到达动作的距离，不是剩余总里程。
- 没有真实路线且未显式开启演示时，动作图标、距离、圆周路线进度和限速牌全部隐藏，不能用直行、`0 m` 或测试限速伪装成可执行导航。
- canonical 离线 Demo Ride 使用 D 栋附近到浪潮总部附近的真实 OSM 道路。白色选中路线与灰色背景道路均来自可核验、物理连通的 OpenStreetMap way，WGS84 坐标统一转换为 GCJ-02 后同场绘制。演示必须保留 `© OpenStreetMap contributors` 署名并遵守 ODbL，详见 [演示数据说明](../shared/demo_fixture/README.md)；iOS 在线演示和正式导航才实时请求高德，响应不固化。
- 普通高德路线接口只返回选中路线，不返回完整周边道路网。正式在线灰色道路层需要高德“交通态势查询”高级 API 的 `extensions=all` / `roads[].polyline`，并须在车载或智能硬件投射前取得高德明确书面授权；未开通、未授权时只显示真实选中路线，不生成假背景道路。
- iOS 恢复连接时的 GATT 建立、事件乱序、可靠握手写入、握手重试、旧会话过滤和退避时机已修正。当前实机连续 3 次 App 冷启动均一次完成两阶段握手，协商帧长 182；锁屏数小时与反复断电仍需按真机门槛长测。
- 侧面 PWR 按住 3 秒显示关机画面并请求 AXP2101 软件关机；若固件卡死，继续按到 4 秒由 PMIC 硬件关机。USB、电池及两者同时接入的实际关机/唤醒行为仍需逐项实测。

### 圆屏连接生命周期

导航尚未可用时不再停留在带 `0 m` 的假导航页，而是由共享 LVGL 显示完整状态：

| 条件 | 圆屏文字 | 图形与动画 |
| --- | --- | --- |
| 手机离线 | `CONNECT PHONE` / `请打开手机应用` | 手机轮廓与慢速环形扫描 |
| BLE 建链或协议握手 | `CONNECTING` / `正在建立连接` | 同一手机图形，扫描速度加快 |
| 从离线进入在线 | `CONNECTED` / `连接成功` | 绿色圆形与勾号轻呼吸，约 920 ms 后自动进入下一状态 |
| 在线但没有有效路线 | `READY TO RIDE` / `请在手机选择目的地` | 黑白路线起终点图形轻呼吸 |
| `route_request_in_flight` | `BUILDING ROUTE` / `正在规划路线` | 白点沿路线图形移动 |
| 已有有效路线或显式本机演示 | 生命周期遮罩隐藏 | 遮罩淡出，显示真正的导航画面 |

常规状态切换先用 140 ms 淡出旧内容，再用 220 ms 淡入新内容；直接从隐藏态出现时
只执行淡入。开启减少动态效果后立即切换，并暂停 40 ms 的生命周期动画时钟。连接
成功画面由 `OFFLINE/CONNECTING → ONLINE` 的真实边沿触发，不由普通快照刷新重复播放。
Web 可用 `?deviceState=offline|connecting|success|ready|planning` 分别固定预览五种遮罩。

## 4. iOS 后台约束

原生应用会声明 `location` 与 `bluetooth-central` 后台模式，并使用持续定位
和 BLE 状态恢复。正常锁屏、切到后台、手机放包里时，系统可以继续交付定位
与 BLE 事件。以下情况无法由应用规避：

- 用户手动从多任务界面强制结束应用；
- 用户关闭定位、蓝牙或撤销权限；
- 手机没电、系统因异常资源占用终止进程；
- 手机与仪表超出 BLE 距离。

因此协议带心跳、超时和完整快照恢复，ESP32 断连时必须明确显示状态，不能
继续把旧速度或旧转向当成实时数据。

## 5. 音乐功能的现实范围

“上一首 / 播放暂停 / 下一首”可以作为附加能力实现；最稳妥的量产路径可能
需要 ESP32 同时提供 BLE HID Consumer Control。第三方 iOS 应用不能通用地
替网易云音乐或系统里任意播放器读取完整曲目信息、也不能通用地“喜欢”。当前
版本只接 Apple Music 的公开 `systemMusicPlayer`：上一首、播放/暂停、下一首和
正在播放信息；协议仍保留能力位，但 App 声明 `like available = 0`，圆屏隐藏
“喜欢”。网易云暂不进入本阶段。
