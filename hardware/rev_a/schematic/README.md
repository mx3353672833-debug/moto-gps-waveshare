# MOTO GPS Rev A schematic

Status: **engineering EVT capture — not released for fabrication**

This directory contains the first electrically connected Rev A schematic for the
custom round navigation board.  It is not the earlier A0 mechanical placeholder.
The checked-in native design targets KiCad 10 and uses an
`ESP32-S3-WROOM-1U-N16R8` (`C3013946`) for the first EVT spin.

## Deliverables

- `moto-gps-rev-a.kicad_sch` — native, openable KiCad 10 schematic.
- `moto-gps-rev-a.kicad_sym` and `sym-lib-table` — project-local symbol library.
- `moto-gps-rev-a.xml` — KiCad intermediate netlist exported from the native schematic.
- `moto-gps-rev-a.pdf` — one-sheet schematic plot for review.
- `schematic-components.csv` — exact reference/value/footprint table.
- `pin-net-map.csv` — every schematic pin, electrical type and assigned net/NC state.
- `erc-rev-a.rpt` — live KiCad 10 ERC report.
- `generate_schematic.py` — deterministic source used to regenerate the design.
- `moto-gps-rev-a.sch` and `moto-gps-rev-a-cache.lib` — generated legacy-format
  audit intermediates; the `.kicad_sch` file is the authoritative editor input.

## Captured circuits

- ESP32-S3 native USB 2.0, EN/BOOT support and manufacturing UART test pads.
- H0175Y003AMT003 V1 1.75-inch 466×466 AMOLED/touch interface using
  CO5300 QSPI and CST820 single-touch I²C signals.
- A likely 31P module-side connector plus separate 31P/0.3 mm FFC path. The
  electrical functions are captured, but the end-to-end connector numbering is
  not frozen until cable/sample continuity confirms Pin 1 and both contact faces.
- USB-C sink attach/current detection with `TUSB320LAI`; the controller alone owns
  CC1/CC2 Rd termination and no parallel 5.1 kΩ pair is fitted.
- `BQ25628E` 1-cell charger/NVDC power path and `TPS63070` 3.3 V buck-boost.
- QMI8658A IMU and IIS2MDC magnetometer on the shared I²C bus. They retain the
  reviewed QMI8658C/LIS2MDL land patterns and pin maps, with firmware ID/axis
  validation required on EVT hardware.
- `LC76GABMD`, low-noise 3.0 V LDO, bidirectional-voltage UART interface,
  open-drain reset, PPS buffer and active-antenna RF path.
- Power/function/reset/boot buttons and seventeen bring-up test points.

Audio, microphones, RTC and SD hardware are deliberately omitted.  Phone media
control is a firmware/BLE concern and does not require those circuits.

## Frozen MCU signals

The generator checks in the mapping in `../ARCHITECTURE_FREEZE.md`: display QSPI
uses GPIO 1/4/5/6/7/12/13/38, touch uses GPIO 2/11 and shared GPIO 14/15 I²C,
GNSS UART uses GPIO 17/18, native USB uses GPIO 19/20, QMI interrupts use GPIO
21/39, charger interrupt uses GPIO 40, GNSS PPS uses GPIO 41, magnetometer DRDY
uses GPIO 42, GNSS open-drain reset drive uses GPIO 47 and Type-C interrupt uses
GPIO 48.  GPIO 0 is BOOT only; strap-sensitive GPIO 3/45/46 remain unused.

## Regeneration

`kiutils` is a build-time serializer only; the generated schematic embeds its
symbols and does not need Python to open.

```sh
python3 -m venv ../../../.venv-hardware
../../../.venv-hardware/bin/pip install -r requirements-build.txt
../../../.venv-hardware/bin/python generate_schematic.py
kicad-cli sch upgrade --force moto-gps-rev-a.kicad_sch
kicad-cli sch erc --exit-code-violations --severity-all \
  -o erc-rev-a.rpt moto-gps-rev-a.kicad_sch
kicad-cli sch export netlist --format kicadxml \
  -o moto-gps-rev-a.xml moto-gps-rev-a.kicad_sch
kicad-cli sch export pdf -o moto-gps-rev-a.pdf moto-gps-rev-a.kicad_sch
```

## Fabrication blockers

This capture must not be sent to JLCPCB until all of the following are closed:

1. Inspect the delivered H0175Y003AMT003 V1 module and a matching 31P FFC. Confirm
   whether the display end is a receptacle rather than a captive flex, then record
   Pin 1, both contact faces, cable orientation, insertion direction, conductor
   continuity, FFC thickness and connector height. J3 is an audited candidate,
   not a physical-fit or pin-order release.
2. Freeze the exact USB-C connector and enclosure opening/Z-height.
3. Independently audit every custom BQ25628E, TPS63070, QMI8658C, LC76G and USB
   ESD land pattern against the current manufacturer package drawing.
4. Validate the BQ25628E/TPS63070 power section on a coupon for cold start,
   charging, USB/battery switchover, 1.5 A load steps and sealed-case temperature.
5. Complete 50 Ω GNSS routing, antenna/RF-window selection and assembled-unit RF test.
6. PCB DRC and the Gerber/drill/BOM/CPL cross-check are complete for R4; repeat
   them after any physical-gate-driven component or footprint change.

The display baseline was updated against the supplier's H0175Y003AMT003 V1
specification; the local controlled copy is
`../references/H0175Y003AMT003_V1.pdf`. It defines the CO5300/CST820 functions,
31 contacts and module mechanics. It does **not** by itself prove how a separate
FFC maps those contacts onto the main-board connector. A geometrically reversed
paper comparison is encouraging, but must not be treated as a frozen reversal;
sample continuity is the release authority.

The LC76GABMD source reviewed for this capture is a single-band,
multi-constellation 1559–1606 MHz receiver.  The RF chain therefore omits the
earlier GPS-only narrow SAW and retains a low-capacitance ESD part plus a tunable
DNP/0 Ω/DNP π network.  It must not be described as L1/L5 hardware without a
different, verified GNSS suffix.
